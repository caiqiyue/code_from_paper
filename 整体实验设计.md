## 三、两算法完整流程说明

### 3.1 创新算法（thesis_platform）完整流程

创新算法的核心机制是：**联邦框架下的差分隐私保护 + Critique 驱动的 Prompt 优化 + 个性化路由/双池生成**。


| 步骤 | 名称                     | 核心模块                                          | 作用                                              | 关键产物                         |
| ---- | ------------------------ | ------------------------------------------------- | ------------------------------------------------- | -------------------------------- |
| 1    | Generation               | `adapters/generators/pretext_prompt_generator.py` | Server LLM 基于当前 prompt 与公开种子生成合成候选 | `generated_samples.jsonl`        |
| 2    | Client Assignment        | `core/round_runner.py`                            | 将 global pool / cluster pool 样本分配给各 client | `client_assigned_samples.jsonl`  |
| 3    | Scoring                  | `adapters/scorers/datainf_real_scorer.py`         | 用`roberta_large` 提取特征并计算影响分数          | `scored_samples.jsonl`           |
| 4    | Bad Sample Selection     | `core/selector.py`                                | 选择 top-k 或随机的“坏样本”                     | `selected_bad_samples.jsonl`     |
| 5    | Retrieval                | `adapters/retrievers/knn_retriever.py`            | 用`all_minilm_l6_v2` 从私有数据中召回相似锚点     | `retrieved_pairs.jsonl`          |
| 6    | Critique Generation      | `adapters/critics/fedtextgrad_qwen_critic.py`     | LLM 对 bad sample 与真实锚点差异生成规则          | `client_critiques.jsonl`         |
| 7    | Prototype Extraction     | `algorithms/prototypes/minilm_mean.py`            | 提取 client 原型向量并可叠加 DP 保护              | `client_prototypes.jsonl`        |
| 8    | Aggregation              | `algorithms/aggregators/dbscan_core.py`           | 规则聚类、注意力排序、记忆融合、原型聚类          | `prompt_update.json`             |
| 9    | Prompt Update            | `core/prompt_updater.py`                          | 生成新的 global / cluster / memory prompt         | `server_prompt.txt`              |
| 10   | Downstream Export / Eval | `evaluation/downstream_eval.py`                   | 导出合成语料，执行大模型/小模型/GLUE 等衍生评测   | `downstream_eval/`、`glue_eval/` |

其完整闭环为：

`生成 -> 打分 -> 选择 -> 召回 -> 批评 -> 聚合 -> prompt 更新 -> 下一轮生成 -> 合成语料导出 -> 下游评测`

### 3.2 PrE-Text 完整流程

PrE-Text 的核心机制是：**差分隐私下的私有演化（Private Evolution）+ Stage2 Bootstrap 扩增 + 下游评测**。


| 步骤 | 名称                | 核心模块                       | 作用                                                       | 关键产物                                   |
| ---- | ------------------- | ------------------------------ | ---------------------------------------------------------- | ------------------------------------------ |
| 1    | 初始化种群          | `stage1.py`                    | 从公开初始化语料中采样初始候选群体                         | 初始 pool                                  |
| 2    | 私有数据嵌入        | `similarity.py`                | 用`all_minilm_l6_v2` 编码私有文本                          | private embeds                             |
| 3    | Lookahead Embedding | `similarity.py`                | 对候选做 lookahead mask-fill 变异并求平均 embedding        | lookahead embeddings                       |
| 4    | FAISS Histogram     | `histogram.py`                 | 统计候选与私有文本的最近邻命中次数                         | histogram                                  |
| 5    | DP Noise Injection  | `histogram.py`                 | 对 histogram 加 Gaussian 噪声形成`(ε, δ)`-DP             | noised histogram                           |
| 6    | Survivor Resampling | `stage1.py`                    | 根据带噪概率重新采样 survivor                              | surviving pool                             |
| 7    | Variation           | `variation.py`                 | 用`roberta_large` 做 MLM mask-fill 变异                    | new candidate pool                         |
| 8    | Stage1 Iteration    | `stage1.py`                    | 重复 lookahead -> histogram -> DP -> resample -> variation | `surviving_text_it*.json`                  |
| 9    | Stage2 Bootstrap    | `bootstrap.py`                 | 用`llama_2_7b_hf` 或其他大模型扩增合成语料                 | `stage2/llama7b_text_syn.json`             |
| 10   | Evaluation          | `run_pipeline` / `run_glue.py` | 执行`eval_small`（默认）、`eval_large`（需配置开启）、`eval_glue`                | `eval_small/`、`eval_large/`、`eval_glue/` |

其完整闭环为：

`Stage1 私有演化 -> Stage2 Bootstrap -> 合成语料 -> 下游评测`

### 3.3 两算法的实验对比焦点

正式实验与测试实验都围绕以下问题展开：

1. 创新算法能否在 **更少轮次** 下达到与 PrE-Text 相当或更好的下游性能。
2. 创新算法的 **Critique / Routing / Privacy / Aggregation** 是否分别贡献了性能提升。
3. 在不同数据集、不同隐私预算、不同模型规模、不同客户端规模下，创新算法是否保持稳定优势。
4. 两个项目的完整执行链路是否都能稳定产出可复核的过程文件和最终结果文件。

## 四、正式实验设计

### 4.1 正式实验目标与核心假设

正式实验用于回答以下论文级问题：

1. **主对比假设**：创新算法在 `jobs` 和 `congressional` 上，能以更少轮次达到不低于 PrE-Text 的效果。
2. **机制有效性假设**：去掉 critique、routing、privacy、memory、聚合策略后，性能会出现可观下降。
3. **隐私效用假设**：随着 `epsilon` 放宽，效用上升，但主算法在同等隐私预算下具有更优平衡。
4. **泛化假设**：创新算法在 `forums`、`microblog` 与跨域 transfer 场景下仍有可用性。
5. **稳健性假设**：不同随机种子下结果波动可控，结论不依赖单次幸运运行。

### 6.3 统一验收标准

无论是正式实验还是测试实验，至少应满足以下验收条件：

1. 命令对应的实验目录已经生成，且 `resolved_config.json` 存在。
2. 主 summary 文件已经生成：创新算法为 `metrics_summary.json`，PrE-Text 也为 `metrics_summary.json`。
3. 过程目录已经生成：创新算法至少存在 `round_000/`，PrE-Text 至少存在 `stage1/`、`stage2/` 及对应 summary。
4. 合成语料文件已经生成：创新算法或 PrE-Text 都应能定位到 `stage2/llama7b_text_syn.json` 或等价可消费语料。
5. 若命令包含下游评测、GLUE、跨域或多种子，则对应的 summary 文件必须在预定位置存在。
6. 实验设计中的“正式实验”和“测试实验”都必须能根据本文档直接定位到过程文件与最终结果文件，而不需要再额外猜测目录结构。

## 七、最终建议

本文档现在分成两条清晰主线：

1. `第四部分` 是论文与最终分析要用的正式实验设计，覆盖核心对比、消融、隐私、聚合、规模、模型、下游任务、跨域与稳健性。
