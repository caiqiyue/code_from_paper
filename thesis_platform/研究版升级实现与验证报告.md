# thesis_platform 研究版升级实现与验证报告

## 1. 结论

当前 `thesis_platform` 已从原有 MVP 骨架升级为一条可运行的“研究版主链”，完成了以下核心补足：

- Prompt 更新已真实进入生成器，而不是只写入元数据。
- `DataInf` / `GRADMM` 已从启发式近似改为基于 frozen embedding + 轻量 probe 的打分流程。
- `IRA` 已正式启用，并要求 `instruction_response` / `pair_alignment` 场景。
- `fedtextgrad_llm` 已替代原启发式 critique。
- `dbscan_attn` / `dbscan_attn_tsgdm` 已实现聚类聚合与跨轮记忆。
- 研究版指标与产物已补齐，包括 `probe_metrics.json`、`aggregation_clusters.json`、`generation_requests.jsonl`、`generation_responses.jsonl`。

## 2. 主要实现项

### 2.1 运行时与配置

- 增加顶层 `llm.client` / `llm.server` 配置入口。
- `ServerContext` 增加 `aggregation_memory`、`generated_history`、`base_prompt`。
- `ClientContext` 增加 `negative_samples`、`text_backend`、`objective_type`、`probe_state`。
- `TransformersTextBackend` 现在支持真实本地 `transformers` 推理，并补了：
  - 模型缓存
  - `negative_log_likelihood`
  - fast tokenizer 失败时回退 slow tokenizer
  - `device_map="auto"` 时输入张量自动对齐到模型首设备

### 2.2 数据层与 Non-IID

- `load_samples()` 支持：
  - `raw_text`
  - `instruction_response`
  - `classification`
- `partition_samples()` 支持：
  - `shuffle_round_robin`
  - `preserve_buckets`
- `preserve_buckets` 会保留顶层 bucket 的 client 归属，不再随机打散。

### 2.3 研究版算法链

- 研究版生成器：`pretext_prompt_llm`
- 研究版 critic：`fedtextgrad_llm`
- 研究版聚合器：
  - `uid_llm`
  - `dbscan_attn`
  - `dbscan_attn_tsgdm`
- 研究版 scorer：
  - `datainf`
  - `gradmm`
  - `ira`

## 5. 数值验证结果

### 5.1 Prompt A/B 敏感性验证

执行：

```bash
conda run -n pretext python -m thesis_platform.scripts.run_experiment --config thesis_platform/configs/experiments/validation/research_prompt_sensitivity_a.yaml
conda run -n pretext python -m thesis_platform.scripts.run_experiment --config thesis_platform/configs/experiments/validation/research_prompt_sensitivity_b.yaml
```

输出目录：

- `outputs/thesis_platform/research_prompt_sensitivity_a`
- `outputs/thesis_platform/research_prompt_sensitivity_b`

关键结果：

- 两个实验都使用真实 tiny 子集：
  - public seed: `6`
  - private train: `12`
- embedder 后端为 `sentence_transformer`，不再是 `HashingEmbedder`
- A/B 两组 `generated_samples.jsonl` 对比结果：
  - 相同条目数：`0 / 4`
- 说明研究版生成器已经真实消费 `initial_prompt`

### 5.2 真实 tiny 子集两轮端到端验证

执行：

```bash
conda run -n pretext python -m thesis_platform.scripts.run_experiment --config thesis_platform/configs/experiments/validation/research_tiny_congressional.yaml
```

- `outputs/thesis_platform/research_tiny_congressional`

- public seed: `9`
- private train: `12`

## 6. 运行时说明

研究版默认模型配置仍保持为：

- client: `thesis_platform/open_model/llama_3_2_3b_instruct`
- server: `thesis_platform/open_model/llama_3_1_8b_instruct`

但本次“极少数据验证”使用的是 `distilgpt2` 验证配置，而不是默认 Llama 3.x。原因是当前 `pretext` 环境中的 `transformers/tokenizers` 版本无法稳定加载本地 Llama 3 tokenizer 文件格式。为保证端到端验证可执行，本次 validation config 采用了当前环境兼容的本地 `transformers` 模型。

这不影响研究版算法链是否已实现；影响的是默认 Llama 3.x 验证配置在当前环境下的可执行性。
