# 基于强化私有选择器的 PrE-Text 增量创新思路

## 0. 文档定位

这是一份介于“研究决策备忘录”和“论文方法章前置方案”之间的文档。  
它不讨论实验设计，不展开论文写作格式，而是集中回答以下问题：

1. `PrE-Text` 的核心弱点到底在哪里。
2. 已有优化工作，例如 `POPri`，为什么虽然性能更强，但并不适合作为当前主线。
3. 我们现在最合适的创新落脚点是什么。
4. 这个创新点是否容易与已有算法雷同。
5. 在不微调大模型的硬约束下，加入创新点后的算法流程应该如何组织。
6. 它与原始 `PrE-Text` 的差异到底在哪里。

当前阶段默认场景是：`单节点验证版`。  
目标不是先解决联邦异构客户端的所有问题，而是先回答一个更基础、更关键的问题：

> 在不微调大模型生成器的前提下，能否通过改进 `PrE-Text Stage 1` 的私有选择器，稳定提升最终合成文本的质量。

只有这个问题先被验证解决得差不多，后续才有必要把它迁移到真正的联邦场景，再研究 `Non-IID`、客户端冲突、用户级 DP 聚合等问题。

---

## 1. 为什么不再把 Prompt 优化当作主线

你之前的单节点创新算法主线大致是：

1. 先生成 100 个候选合成样本。
2. 找出 10 个坏样本。
3. 为每个坏样本检索相似的私有样本。
4. 把 `(坏合成样本, 好私有样本)` 样本对交给大模型生成批评。
5. 融合批评，迭代优化生成提示词。
6. 用优化后的提示词生成最终大量合成样本。

这条线的问题已经被你自己的实验暴露得很清楚：

- 坏样本、相似私有样本、生成出来的批评，经常是重复的、近似的。
- 批评链路提供的信息熵不高，更多是在重复“局部缺点”，而不是持续发现新的全局分布问题。
- 经多轮批评改写后，提示词容易被少量坏例牵着走，反而破坏初始提示词本来就具备的整体分布覆盖。
- 最终表现为：某些数据集上略优于 `PrE-Text`，但整体逻辑经不起推敲，因为收益来源并不清楚。

因此，当前最合理的研究收缩方向不是继续强化“批评-检索-聚合-改 Prompt”这条链，而是承认一个更重要的事实：

> 问题的根源大概率不在 Prompt 改得不够聪明，而在于 `Stage 1` 选出来的 seed 本身就不够好。

换句话说，如果最初进入 `Stage 2` 的 seed 数据质量就偏弱，那么后面无论做 bootstrap 扩增、一次性补充 prompt，还是更复杂的后处理，都会受到上限约束。

## 2. 原始 PrE-Text 的算法流程

为了讨论创新点，先把 `PrE-Text` 的核心流程重新压缩一下。

### 2.1 Stage 1: 生成 DP seed data

`PrE-Text` 的第一阶段负责从公共初始候选和私有数据之间建立联系，产出一批可用于扩增的 `DP seed`。

大致流程如下：

1. 从公共初始化集合中采样得到当前候选 synthetic population。
2. 用冻结的文本编码器计算候选文本与私有文本之间的 embedding 相似关系。
3. 对每条私有样本，只找到它最接近的 synthetic candidate，即 `Top-1 nearest neighbor`。
4. 统计每个 synthetic candidate 被多少私有样本“投票命中”，得到最近邻直方图。
5. 对直方图加噪、阈值截断、重采样幸存样本。
6. 用冻结的 `mask-filling` 模型继续做变异，进入下一轮。
7. 多轮结束后，保留所有轮次的幸存样本，作为 `DP seed set`。

### 2.2 Stage 2: Expand

第二阶段不再接触私有数据，只把 `DP seed set` 交给公共大模型做 bootstrap 扩增，生成大量 synthetic corpus。

这是 `PrE-Text` 最重要的结构性特点：

- 隐私损失集中在 `Stage 1`
- 大模型生成器不在私有数据上微调
- `Stage 2` 只是后处理式扩增

这套骨架本身没有问题，真正脆弱的是 `Stage 1` 的私有候选选择机制。

## 3. PrE-Text 的核心弱点到底在哪里

当前最重要的判断是：`PrE-Text` 的主弱点不是“Stage 2 的 LLM 不够强”，而是“Stage 1 的私有选择器太弱”。

### 3.1 弱点一：Top-1 最近邻投票过于脆弱

`PrE-Text` 的私有反馈几乎可以概括成一句话：

> 每个私有样本只给它最接近的一个 synthetic candidate 投票。

这个设计的问题非常明显：

- 只保留 `Top-1`，会严重浪费排名信息。
- 当两个候选都比较接近私有样本时，只有第一名得到支持，第二名的有用信息被直接丢掉。
- 在少样本场景中，`Top-1` 统计本来就稀疏，再叠加差分隐私噪声后，更容易失真。
- 最终导致高质量候选和一般候选之间的差别被抹平，弱信号被噪声吞掉。

### 3.2 弱点二：它只看“像不像”，不看“值不值得留”

原始 `PrE-Text` 更像一个几何相似度驱动的选择器。

它的隐含逻辑是：

> 如果候选文本和私有文本在 embedding 空间里接近，那么这个候选就值得保留。

但这个逻辑并不牢靠，因为：

- 接近不等于高质量。
- 接近不等于有任务效用。
- 接近不等于细节充分。
- 接近不等于不重复。

一个候选文本即使和很多私有样本都很接近，也可能只是：

- 模板化表达
- 过于通用的表述
- 缺少任务关键细节
- 与已选 seed 高度冗余

因此，原始 `PrE-Text` 的选择器容易把“通用但平庸”的文本当成优质 seed 留下来。

### 3.3 弱点三：低分样本的信息被浪费

在 `PrE-Text` 里，低支持度候选基本只是被淘汰。

这意味着它没有真正利用“反例信息”：

- 哪些候选虽然接近，但过于泛化
- 哪些候选虽然有一定支持，但和已有 seed 重复
- 哪些候选代表的是噪声模式，而不是私有分布核心

也就是说，原始方法只在问“谁应该被留下”，却没有充分问“谁不应该被留下，以及为什么”。

### 3.4 弱点四：seed 质量瓶颈会传导到 Stage 2

`Stage 2` 再强，也只是对 `Stage 1` 的 seed 做扩增。

如果 seed 本身存在以下问题：

- 覆盖不足
- 冗余过高
- 过于通用
- 细节不足

那么 `Stage 2` 只是在放大这些问题，而不是根治它们。

因此，`PrE-Text` 的真正上限，在很大程度上已经被 `Stage 1` 决定了。

## 4. 现有优化工作已经做了什么，以及它们还有什么问题

当前和 `PrE-Text` 最相关的已有工作，大致分为三类：

1. `改生成器`
2. `改选择器`
3. `改 Prompt/反馈机制`

### 4.1 POPri：性能强，但代价也大

`POPri` 的核心做法是把客户端反馈整理成 `preference pairs`，再用 `DPO/偏好优化` 微调服务器端生成器。

它的优点很明显：

- 性能确实强。
- 反馈利用率更高。
- 不再只是简单投票，而是把正负偏好都用上了。

但它的问题也很明确：

- 它微调了大模型生成器。
- 算力消耗显著高于 `PrE-Text`。
- 资源要求高，复现实验成本高。
- 研究问题已经从“training-free synthetic data generation”转向了“preference-based model optimization”。

因此，`POPri` 不能作为当前主线直接照搬。  
它可以作为一个很重要的参照物，用来说明：

> 即便 `POPri` 性能更强，它解决问题的方式也已经越过了我们的硬边界，因为它依赖微调生成器，而我们当前阶段明确不允许这样做。

### 4.2 WASP：给了选择器增强的启发，但不能直接拿来当创新点

`WASP` 最有价值的启发有两个：

1. 不要只做 `Top-1`
2. 不要只保留高质量样本，低质量样本也可以提供反向信号

这对 `PrE-Text` 很有针对性，因为它正好能缓解：

- 投票过稀
- 信息利用不足
- 低分样本被直接浪费

但如果直接照搬成：

- `Top-k 衰减投票`
- 高低质量样本对比 prompt
- 多 PLM 动态加权

那就会和 `WASP` 非常接近。  
所以 `WASP` 只能借思想，不能借整套写法。

### 4.3 PCEvolve：也在改选择器，但重心偏“对比式选择”

`PCEvolve` 的价值在于它指出了一个很尖锐的问题：

> 在少样本条件下，传统高斯噪声投票和简单接受机制，会让本来就弱的私有信号进一步塌陷。

它提供的启发是：

- 单点相似度不够
- 要引入关系性信号
- 要考虑更强的 private selector

但如果你的创新写成：

- `contrastive filter`
- `adapted exponential mechanism`
- `few-shot contrastive selector`

就会和 `PCEvolve` 太像。  
因此，它更适合作为“问题动机来源”，而不是直接照搬的方法来源。

### 4.4 RewardDS：强调质量控制，但更适合做后处理，不适合当前主线

`RewardDS` 的启发在于：

> 生成后先做质量控制，再谈下游训练。

这个想法是对的，但它通常需要：

- 额外的质量估计器
- 更复杂的过滤与精炼链路
- 容易把方法主线从“selector design”扩展成“质量控制框架”

这对当前阶段来说太重了。

### 4.5 FedTextGrad / FedDTPT / FedPHA / FedCALM：有启发，但不应成为当前主线

这些工作的重要价值不在于让我们去复现它们，而在于帮助我们明确：

- 多轮文本反馈聚合容易冗余、爆长度、失稳
- 简单平均会丢失有效信号
- 冲突感知和分歧约束是有价值的

但它们的问题是：

- 更偏联邦优化层
- 更偏 prompt/textual gradient 主线
- 很容易把方法做大

而你当前阶段恰恰不想再回到这个方向。

因此，它们只适合作为“思想边界”，不适合作为当前算法主轴。

## 5. 我们的创新点应该落在哪里

结合前面的分析，当前最合适的创新落脚点可以概括成一句话：

> 不改 Stage 2，不微调大模型，不做多轮 Prompt 优化，只重设计 `PrE-Text Stage 1` 的私有选择器。

这意味着当前方法的创新不应该写成：

- 一个新的联邦合成框架
- 一个新的文本梯度方法
- 一个新的大模型自优化流程

而应该写成：

> 一个 `selector-centric` 的增量创新：在 `training-free` 约束下，提升 `PrE-Text` 的 seed quality。

### 5.1 主推荐路线

`路线 A：固定生成器 + 多信号私有种子选择器`

它的核心思想是：

- 保留 `PrE-Text` 的两阶段骨架
- 保留固定的大模型生成器
- 保留 Stage 2 bootstrap 扩增
- 只改 Stage 1 的私有候选打分与接受机制

### 5.2 备选路线

`路线 B：多信号私有种子选择器 + 一次性弱 Prompt 补充`

它和主路线的区别只在于：

- 在 `Stage 1` 选出更高质量 seed 后
- 允许做一次很弱的 Prompt 补充
- 但不做多轮批评改写，不引入文本梯度主线

### 5.3 为什么路线 A 更值得推荐

因为路线 A：

- 最干净
- 最不容易回到你之前失败的批评链路
- 最容易和 `POPri` 拉开距离
- 最容易和 `FedTextGrad` 拉开距离
- 最适合先在单节点验证“合成数据质量”问题

因此，本文档后续的详细流程都围绕 `路线 A` 展开，`路线 B` 只保留为备选。

---

## 6. 我们的创新点是否会和别人雷同

当前路线不是没有风险，但风险是可控的。

### 6.1 不会雷同的部分

这条路线与已有工作存在清晰边界：

- 它不同于 `POPri`
  - `POPri` 通过偏好优化微调生成器
  - 我们明确不微调生成器

- 它不同于 `FedTextGrad`
  - `FedTextGrad` 走文本梯度、批评、聚合、Prompt 更新
  - 我们不把文本批评当主线

- 它不同于 `RewardDS`
  - `RewardDS` 更偏生成后质量控制与精炼
  - 我们把核心创新压在 `Stage 1 selector`

- 它不同于原始 `PrE-Text`
  - `PrE-Text` 的骨架被保留，但关键的私有 seed 接受机制被重新设计

### 6.2 容易雷同的部分

如果写法不小心，还是可能靠近：

- `WASP`
  - 如果只说 `Top-k vote + 正负样本对比`
- `PCEvolve`
  - 如果只说 `contrastive selector + EM`
- `DataInf`
  - 如果直接声称“影响函数驱动的私有选择器”，但又没有完整影响力理论和实现

### 6.3 如何控制雷同风险

最稳的写法不是：

> 我们把 `Top-1` 改成了 `Top-k`

也不是：

> 我们加入了对比式过滤

而应该写成：

> 我们重新定义了 `Stage 1` 的私有 seed 选择目标，使其联合优化 `私有覆盖度`、`重要性权重`、`冗余惩罚` 和 `通用性抑制`，并且不改变 Stage 2 生成器与 bootstrap 主干。

这才是当前最安全的创新边界。

## 7. 主推荐路线 A 的核心创新点

主路线不是简单替换一个小组件，而是把 `Stage 1 selector` 从“单信号几何投票器”升级为“多信号质量感知选择器”。

可以把它拆成 4 个核心创新点。

### 创新点 1：把 Top-1 投票改成加权 Top-Q 排序投票

原始 `PrE-Text` 的问题是每条私有样本只投给一个候选。  
我们的改法是：

- 每条私有样本不只看一个候选，而是看 `Top-Q` 个候选
- 按排名分配衰减权重
- 第一名权重最大，但第二名、第三名仍保留部分支持信号

这样做的效果是：

- 降低投票稀疏性
- 减弱 Top-1 偶然误匹配的影响
- 在少样本条件下更稳

### 创新点 2：引入私有样本的重要性先验

不是所有私有样本都应该拥有同样的话语权。

例如：

- 高频通用样本
- 低信息密度样本
- 模板化样本

它们不应该主导 selector。

因此，我们在客户端内部先为私有样本分配一个轻量的重要性先验，这个先验不直接写成完整 influence function，而是写成：

`DataInf-inspired sample importance prior`

它的作用是：

- 强化代表性样本
- 适度抬高稀缺但高价值样本
- 避免大量普通样本把 selector 拉向“通用但平庸”的方向

### 创新点 3：在接受机制中加入冗余惩罚与通用性抑制

一个候选被很多私有样本支持，不一定说明它高质量；它也可能只是：

- 过于通用
- 与已有候选高度重复
- 非常安全但没有信息增量

因此，我们不只计算支持度，还对候选加入两个负向项：

1. `冗余惩罚`
   - 如果候选与已选 seed 很像，则被惩罚

2. `通用性抑制`
   - 如果候选与公共初始化模板过于接近，或者只是“泛化套话”，则被惩罚

这样，selector 选择的不再是“最像”的文本，而是“最值得进入 seed set”的文本。

### 创新点 4：低分候选不再被浪费，而是被用于拒绝边界学习

我们不再像你之前的路线那样，把低分样本拿去做复杂批评。

而是让低分候选只承担一个更稳定的作用：

- 帮助定义“什么样的候选不该进入 seed set”
- 作为 hard negative，校准接受阈值
- 帮助筛掉通用但平庸的模式

这就保留了“负样本信息”，但避免重新走回不稳定的批评链路。

## 8. 主推荐路线 A 的详细算法流程

下面给出当前最推荐的、加入创新点后的完整流程。  
这是 `单节点验证版` 的推荐算法流程。

为了清楚起见，记号如下：

- `D_priv`：私有语料
- `D_init`：公共初始化语料
- `G`：固定的大模型生成器
- `E`：冻结的文本编码器
- `C_t`：第 `t` 轮候选集合
- `S_t`：第 `t` 轮最终保留的 seed 集合

### 阶段 0：固定生成器与固定扩增骨架

首先明确边界：

- 不微调 `G`
- 不引入 DPO、LoRA、RLHF
- 不把大模型训练成新的生成器
- 不把多轮 Prompt 优化作为主线

这意味着整个算法一开始就把问题限定为：

> 我们要做的不是让生成器变强，而是让进入生成器扩增链路的 seed 变得更强。

### 阶段 1：生成候选 synthetic population

这一阶段与 `PrE-Text` 保持大体一致：

1. 从 `D_init` 采样初始候选。
2. 使用固定生成器或固定变异器产生当前轮候选集合 `C_t`。
3. 对 `C_t` 中每条候选文本做基础清洗，例如：
   - 去空
   - 去异常短文本
   - 去明显格式损坏文本

这一步的目标只是提供候选池，而不在这里做核心创新。

### 阶段 2：为私有样本建立重要性先验

对私有语料 `D_priv` 中的每条样本 `x`，先计算一个重要性权重 `w(x)`。

这个权重不是完整影响函数，而是轻量的代表性先验，可由以下信息组合得到：

1. `代表性`
   - 该样本是否接近私有语料内部的中心分布

2. `稀缺性`
   - 该样本是否代表一个较少出现但重要的模式

3. `信息密度`
   - 该样本是否过于模板化、过于口水化

因此，后续投票时，不是所有私有样本都平权，而是：

`重要样本的话语权更高，通用样本的话语权更低`

### 阶段 3：用加权 Top-Q 排序投票替换 Top-1 直方图

对每条私有样本 `x`：

1. 用冻结编码器 `E` 计算它与候选集合 `C_t` 中各候选的相似度。
2. 找到 `Top-Q` 个最近候选，而不是只找第一个。
3. 按排名给这 `Q` 个候选分配衰减权重，例如：
   - rank 1: `1.0`
   - rank 2: `0.6`
   - rank 3: `0.3`
4. 再乘上该私有样本的重要性先验 `w(x)`。

于是，某个候选 `c` 的基础支持度不再是简单命中次数，而是：

`private support(c) = 所有私有样本对 c 的加权排序支持之和`

这一步是整个创新算法的第一核心。

它解决的是：

- 原始 `PrE-Text` 投票过稀
- 单点命中不稳
- 第二好、第三好候选的信息被浪费

### 阶段 4：加入通用性抑制

仅仅有高支持度还不够，因为某个候选也可能只是“很像常见套话”。

因此，对每个候选 `c` 再定义一个 `generic penalty(c)`：

- 如果 `c` 过于接近公共初始化语料
- 如果 `c` 与常见模板表达过近
- 如果 `c` 的词汇与语义结构明显过于安全、过于宽泛

则对其加惩罚。

直观上，这一步的目的是：

> 不让 selector 把“泛化但无增量”的文本误认为高质量 seed。

### 阶段 5：加入冗余惩罚

即使某个候选私有支持度很高，它也不一定应该进入最终 seed set。  
因为它可能和已经选中的候选过于重复。

因此，对候选再加入一个 `redundancy penalty(c)`：

- 若与已选 seed 高度相似，则惩罚更大
- 若提供新的结构、新的措辞、新的细节补充，则惩罚更小

这一步的作用是：

- 提升 seed set 的覆盖度
- 降低重复扩增的风险
- 为后续 Stage 2 提供更丰富的高质量种子

### 阶段 6：构造最终接受分数并选出 seed set

对于每个候选 `c`，我们不再只看直方图计数，而是定义一个更完整的接受分数：

`accept score(c) = private support(c) - lambda1 * generic penalty(c) - lambda2 * redundancy penalty(c)`

然后根据该分数：

1. 选出高质量候选构成 `S_t`
2. 将明显低分候选保留为 hard negative 集合 `R_t`

这里的 `R_t` 不再进入复杂批评链，而只是帮助：

- 校准下一轮阈值
- 防止通用模板再次被反复选入

### 阶段 7：可选的轻量变异，但不做多轮 Prompt 改写

如果当前轮仍保留 `PrE-Text` 原有的变异机制，那么：

- 只对 `S_t` 中的高质量 seed 做轻量 mask-fill 变异
- 不引入大模型批评
- 不引入多轮 Prompt 聚合
- 不引入文本梯度摘要

换句话说，selector 负责“选对样本”，变异器只负责“在正确样本附近扩展局部多样性”。

### 阶段 8：固定 Stage 2 做 bootstrap 扩增

在 `Stage 1` 结束后，把最终高质量 seed set 送入固定的 `Stage 2`：

1. 固定 prompt 组织方式
2. 固定生成器 `G`
3. 固定 bootstrap 扩增策略

此处不再做主创新。

这一步的意义是：

> 用更强的 seed 去喂同样的 Stage 2，观察最终 synthetic corpus 是否自然提升。

如果这个策略成立，那么可以得到一个非常重要的研究结论：

> 在不微调大模型的前提下，真正决定最终合成文本质量的关键，不是 Prompt 改写链的复杂程度，而是 `Stage 1 selector` 是否足够强。

---

## 9. 备选路线 B 的流程

路线 B 不作为主推荐，只作为备选。

它与路线 A 的前半段完全相同，唯一差别在于：

- 在 `Stage 1` 得到最终 seed set 后
- 允许做一次很弱的 Prompt 补充
- 这个补充不来自多轮批评，不来自文本梯度聚合
- 只来自高质量 seed 的统计性总结

例如：

- 从 seed 中抽取高频结构模式
- 从 seed 中抽取应保留的风格约束
- 把这些内容作为一次性附加说明补进 Stage 2 prompt

它之所以只保留为备选，是因为：

- 容易再次把问题带回 Prompt 优化
- 也更容易与 `FedTextGrad` 一类方法的叙事靠近

因此，除非路线 A 明显不够，否则不建议把路线 B 作为第一主线。

---

## 10. 加入创新点后的流程，与原始 PrE-Text 的核心区别

下面把两者并排对照。

| 维度 | 原始 PrE-Text | 当前推荐路线 A |
|---|---|---|
| 方法主轴 | 两阶段 PE + bootstrap | 两阶段骨架不变，只重设计 Stage 1 selector |
| Stage 1 私有反馈 | Top-1 最近邻直方图 | 加权 Top-Q 排序投票 |
| 私有样本权重 | 默认平权 | 引入重要性先验 |
| 候选接受依据 | 相似度命中统计 + 噪声 + 阈值 | 支持度 + 通用性抑制 + 冗余惩罚 |
| 低分候选处理 | 直接淘汰 | 保留为 hard negative，用于拒绝边界学习 |
| Prompt 更新 | 原始骨架内不强调复杂 prompt 自优化 | 主路线中不依赖多轮 Prompt 改写 |
| Stage 2 | 固定扩增 | 固定扩增，不作为主创新 |
| 研究重点 | 把 PE 搬到 federated text | 在 training-free 约束下强化 Stage 1 seed quality |

因此，两者最大的区别不是“换了一个大模型”，也不是“又加了一条批评链”，而是：

> 原始 `PrE-Text` 解决的是“如何在联邦文本场景下把 PE 跑起来”；  
> 当前推荐路线要解决的是“在同样不微调 LLM 的前提下，如何把 Stage 1 的 seed 选得更准、更稳、更不冗余”。

---

## 11. 这条路线能否缓解 PrE-Text 的缺点

答案是：`能，而且是有针对性的缓解`。

### 11.1 它能缓解投票稀疏问题

因为 `Top-Q` 排序投票显著强于 `Top-1` 命中。

### 11.2 它能缓解“只看相似度”的问题

因为我们不是只保留“最近”的文本，而是保留“最值得进入 seed set”的文本。

### 11.3 它能缓解 seed 冗余问题

因为冗余惩罚直接进入接受目标。

### 11.4 它能缓解通用套话被误选的问题

因为加入了通用性抑制。

### 11.5 它能缓解你之前算法中 Prompt 过拟合坏例的问题

因为主路线不再依赖多轮批评和多轮 Prompt 改写。

换句话说，这条路线的价值不在于“更复杂”，而在于“更克制、更聚焦”。

---

## 12. 当前最合理的结论

基于现有实验经历、相关论文笔记和当前研究边界，当前最合理的结论是：

1. 不应继续把“坏样本-好样本-批评-多轮改 Prompt”作为主创新。
2. 当前最适合的主问题是：`PrE-Text Stage 1 私有选择器太弱`。
3. 当前最合适的创新路线是：`固定生成器 + 多信号私有种子选择器`。
4. 当前最值得保留的备选路线是：`多信号私有种子选择器 + 一次性弱 Prompt 补充`。
5. 这条主线不微调大模型，和 `POPri` 有清晰边界。
6. 这条主线也不回到 `FedTextGrad` 的文本梯度主线，因此不会和你之前已被实验否定的思路缠绕在一起。

最终，当前阶段最值得坚持的研究判断可以概括成一句话：

> 对于单节点阶段的文本合成数据质量问题，最值得做的不是更复杂的 Prompt 自优化，而是更强、更稳、更克制的 `Stage 1 private selector`。
