## 一、完整版第三版算法设计（理论目标）

### 1.1 算法核心思想

第三版创新算法 **FedText-Proto** 是基于**原型锚点的个性化联邦提示词优化框架**，旨在解决 Non-IID 数据分布场景下的文本合成数据优化问题。核心创新是引入**原型向量 (Prototype)** 作为客户端与服务端之间的分布坐标，实现精准的个性化路由。

### 1.2 完整算法四阶段流程

#### 第一阶段：客户端多维度辅助信息提取与传输

**目标**: 从单一文本反馈升级为包含"指令、坐标、权重"的三维结构化反馈

**步骤 1.1: 效用驱动的坏样本诊断**
- 客户端 k 收到服务端用 P_t 生成的合成样本 x_syn
- 利用本地私有验证集，通过 DataInf（基于梯度的影响函数）评估 x_syn 对本地模型损失的恶化程度
- 将恶化程度映射归一化为效用奖励分数 R_k ∈ [0, 1]
- R_k 越大，代表该合成样本"毒性"越强

**步骤 1.2: 语义原型的锚定提取**
- 针对毒性最高的 x_bad，召回对应的本地真实高质量样本 x_real
- 通过轻量级冻结的特征提取器（如 BERT/MiniLM 的 Embedding 层），计算真实样本的均值特征向量
- 输出局部语义原型向量 Z_k = mean(Embed(x_real))
- 代表该客户端独特的数据分布流形

**步骤 1.3: 文本化梯度生成**
- 本地小模型（如 Qwen-1.5B）对比 (x_bad, x_real)
- 生成自然语言修改意见 g_text^k

**步骤 1.4: 三元组打包上传**
- 客户端打包上传三元组 Γ_k = {g_text^k, Z_k, R_k}

#### 第二阶段：服务端基于原型的概率对齐与加权聚类

**目标**: 在高维空间中，利用"分布坐标"而不是"字面意思"进行精准聚类

**步骤 2.1: 隐空间原型聚类**
- 服务端收到所有 Γ_k 后，先看原型 Z_k
- 在多维隐空间中，对所有原型向量 {Z_1, Z_2, ..., Z_N} 应用 GMM 或 DBSCAN
- 将 N 个客户端严格划分为 M 个非重叠的语义簇 (Clusters)

**步骤 2.2: 效用加权的注意力分配**
- 在同一簇 C_m 内部，不同客户端受害程度不同
- 服务端利用效用分数 R_k 对同簇内的文本梯度进行加权
- α_k = exp(R_k) / Σ exp(R_i)
- 确保痛点最深的客户端在后续冲突消解中拥有最大"话语权"

#### 第三阶段：SVD 冲突解耦与 KKT 缓解投射

**目标**: 在同一簇内，通过严格的数学空间投射，剥离有效建议，拦截相互打架的"恶性冲突"

**步骤 3.1: 正交解耦提取**
- 将簇内的文本梯度转化为文本 Embedding 向量
- 应用 SVD 奇异值分解
- 第一奇异向量（主成分方向）代表该簇所有人的共识性修改意见
- 剩余正交方向代表局部的个性化意见

**步骤 3.2: 有害冲突拦截 (KKT 条件)**
- 检查文本向量之间的余弦相似度
- 若向量 v_a 与 v_b 的点积小于 0（夹角 > 90°），触发恶性冲突
- 利用 KKT 条件进行梯度手术
- 将弱势方的冲突分量向强势方的法平面进行正交投影
- 输出绝对安全的"无冲突核心指令集"

#### 第四阶段：异构双提示词架构重构与下发

**目标**: 拒绝"一刀切"，实现"求同存异"的定制化合成数据生成

**步骤 4.1: 全局共享提示词生成**
- 服务端 LLM 将所有 M 个簇的无冲突主成分翻译为全局基座提示词 P_global^{t+1}

**步骤 4.2: 本地定制提示词生成**
- 针对每个特定簇 m，翻译成该簇专属的定制提示词 P_local^{t+1, m}

**步骤 4.3: 定向路由下发**
- 服务端采用组合 Prompt = [P_global^{t+1} ⊕ P_local^{t+1, C_m}] 进行生成
- 按比例混合：α 份个性化数据 + (1-α) 份全局数据

## 二、当前平台实际实现的算法流程

### 2.1 当前实现的核心架构

```
ExperimentRunner
    ├── Preflight (资产检查)
    ├── PrivacyLedger (隐私预算记账 - 可选)
    ├── TextBackends (服务端+客户端 LLM)
    ├── Public Seed Samples 加载
    └── ClientContexts 构建 (联邦数据分区)
            │
            ▼
    RoundRunner.run_round()
            │
            ▼
    服务端生成阶段
        global_pool = Generator.generate(global_ctx)
        cluster_pool = Generator.generate(cluster_ctx)  # round > 0 时
            │
            ▼
    客户端样本分配
        personalized_mix_ratio = 0.7 (70% cluster + 30% global)
            │
            ▼
    客户端并行处理
        1. Scorer.score() → influence_score (R_k 来源)
        2. select_top_k() → bad_samples
        3. Retriever.retrieve() → PairedSample
        4. Critic.critique() → Critique
        5. Prototype.extract(weight=R_k_utility) → PrototypeFeedback
            │
            ▼
    服务端聚合阶段 (DBSCANAttnTSGDMAggregator)
        1. _build_rule_entries(critiques, r_k_by_client) ← R_k 已注入
        2. _project_conflicting_rules() ← KKT 正交投影
        3. _cluster_rule_entries() / _rank_clusters() ← 注意力加权
        4. _svd_rank_rule_entries() ← SVD 排序
        5. → PromptUpdate (global_rules + cluster_rules)
            │
            ▼
    Prompt 更新与路由
        server_ctx.prompt_text = apply_prompt_update()
        cluster_prompts = render_cluster_prompt()
```

### 2.2 隐私机制：可选设计

**关键设计**: 隐私保护完全可选，不选择则不加入任何隐私操作

**privacy.enabled = False（默认/无隐私保护）**:
```
PrivacyLedger 创建但不使用
privacy_spent = 0.0（不消耗任何预算）
实验流程完全独立运行，无隐私相关开销
```

**privacy.enabled = True（隐私保护模式）**:
```
PrivacyLedger 启用 proxy accounting
privacy_spent = sample_count × sample_cost + critique_count × critique_cost + upload_token_count × upload_token_cost
epsilon/delta 预算可设置（当前为 proxy 记账，非真实 DP）
```
