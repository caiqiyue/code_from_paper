# 2026-03-31 00:50 测试错误排查与修复

## 背景

在 `experiment` 虚拟环境中执行以下自测时，出现了 4 个失败点：

```powershell
conda run -n experiment python -m unittest discover -s thesis_platform/tests -p "test_thesis_platform*.py" -v
conda run -n experiment python -m unittest thesis_platform.tests.test_lora_gradients -v
```

其中：

- `test_thesis_platform*.py` 中有 2 个错误
- `test_lora_gradients.py` 中有 2 个错误

## 根因

### 1. 两条 pipeline 测试把实验输出目录写死了

受影响测试：

- `thesis_platform/tests/test_thesis_platform_research.py`
- `thesis_platform/tests/test_thesis_platform_v3.py`

现象：

- 测试代码直接假设实验输出目录是 `tmp_research` 或 `tmp_v3`
- 但 `ExperimentRunner` 当前实现会为每次运行附加 UTC 时间戳，实际输出目录形如：

```text
<output_root>/<experiment_id>_YYYYMMDD_HHMMSS
```

对应实现：

- `thesis_platform/core/experiment_runner.py:58`

因此测试会去读一个不存在的目录，报 `FileNotFoundError`。

### 2. 两条 LoRA scorer 初始化测试没有打开 hashing fallback

受影响测试：

- `thesis_platform/tests/test_lora_gradients.py`

现象：

- 测试配置显式设置了：
  - `use_real_gradients=False`
  - `feature_model=None`
- 但没有设置 `allow_hashing_fallback=True`

当前 scorer 实现中：

- `DataInfRealScorer` 和 `GradMMRealScorer` 在 `use_real_gradients=False` 时会调用 `build_feature_encoder(...)`
- 如果既没有配置 `feature_model`，又没有允许 hashing fallback，则会直接抛错：

```text
RuntimeError: No feature model configured and hashing fallback is disabled.
```

对应实现：

- `thesis_platform/adapters/scorers/datainf_lora_scorer.py`
- `thesis_platform/adapters/scorers/gradmm_lora_scorer.py`
- `thesis_platform/models/features.py:114`

### 3. scorer 构造失败后析构函数不够稳健

现象：

- 当构造函数在 `_gradient_extractor` 赋值前抛错时，`__del__` 再访问 `self._gradient_extractor` 会触发二次 `AttributeError`

这不是当前主失败原因，但属于真实代码缺陷。

## 修复内容

### 1. 修复 pipeline 测试目录定位方式

改动：

- 不再硬编码 `tmp_research` / `tmp_v3`
- 统一改为使用 `ExperimentRunner.run()` 返回的 `summary["experiment_dir"]`

受影响文件：

- `thesis_platform/tests/test_thesis_platform_research.py`
- `thesis_platform/tests/test_thesis_platform_v3.py`

### 2. 修复 LoRA scorer 初始化测试配置

改动：

- 在两条初始化测试配置中显式加入：

```python
"allow_hashing_fallback": True
```

这样测试语义与注释“Use feature fallback for testing”保持一致。

受影响文件：

- `thesis_platform/tests/test_lora_gradients.py`

### 3. 修复 scorer 析构时的属性访问风险

改动：

- 在 `DataInfRealScorer` / `GradMMRealScorer` 构造函数最开始就初始化：
  - `_gradient_extractor`
  - `_grad_cache`
- 在 `__del__` 中改为使用 `getattr(self, "_gradient_extractor", None)` 做保护

受影响文件：

- `thesis_platform/adapters/scorers/datainf_lora_scorer.py`
- `thesis_platform/adapters/scorers/gradmm_lora_scorer.py`

## 结论

这次测试错误的根因不是环境依赖不满足，而是：

- 部分测试对输出目录命名的假设已经过时
- 两条 fallback 测试的配置与当前 scorer 行为不一致
- scorer 析构逻辑存在一个次级稳健性缺陷

修复后，测试与当前实现语义重新对齐，代码层面的析构健壮性也得到补强。
