# 联邦版 PrE-Text 实验实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `PrE-Text/pretext_platform` 内落地一套联邦架构版本的 PrE-Text 实验流程，使其能够在多客户端分区下完成联邦生成，并产出可直接进入现有单机下游评测链路的最终全局合成语料。

**Architecture:** 保持 `PrE-Text` 的 `stage1/bootstrap/stage2` 算法本体不变，只新增联邦实验编排层。客户端每轮仅执行 `stage1` 并上传 surviving texts，服务端每轮统一执行全局 `bootstrap -> stage2`，最终只保留最后一轮的全局合成语料。

**Tech Stack:** Python、YAML 配置驱动、`PrE-Text/pretext_platform` 现有算法模块、联邦创新算法同口径数据分区规则、JSON 实验产物。

---

## 1. 文档目标与适用范围

本计划只描述联邦版 PrE-Text 的完整实验机制，不展开到具体代码实现细节。重点是把以下内容讲清楚：

- 完整实验流程
- 各阶段输入与输出
- 内部处理逻辑
- 产物组织方式
- 开发完成后必须达到的效果
- 如何验证实验链路正确

本计划不覆盖：

- 单节点版 PrE-Text 的重构
- `stage1/bootstrap/stage2` 算法内部改写
- 联邦下游评测
- 个性化联邦生成
- 联邦创新算法中的路由、聚类、提示词聚合等机制迁移

## 2. 目标系统定义

联邦版 PrE-Text 是一个新的实验形态，不是对单节点版流程的替换。

其目标是：

- 在 `PrE-Text/pretext_platform` 中新增联邦实验执行能力
- 完全复用联邦创新算法的数据分区规则
- 让多客户端私有文本先在本地执行 `stage1`
- 由服务端统一完成每轮的 `bootstrap -> stage2`
- 输出一份最终全局合成语料，供后续单机下游评测复用

最终形成的联邦实验口径必须与联邦创新算法保持可对照性，尤其是：

- 客户端数量
- 客户端数据分区口径
- 外层联邦轮次概念
- 隐私账本记录层级
- 最终轮产物作为正式实验输出的口径

## 3. 总体实验流程

联邦版 PrE-Text 的完整实验流程分为 8 个阶段。

### 阶段 0：实验配置解析

系统启动后首先读取联邦版 PrE-Text YAML 配置。

输入：

- 实验配置文件
- 原始真实数据集
- 运行目录和实验 ID

输出：

- 解析后的联邦实验配置
- 实验根目录
- `resolved_config.json`

内部处理逻辑：

- 判断当前模式是 `federated_pretext`
- 解析联邦相关字段，例如 `rounds`、`num_clients`、`partition_strategy`
- 解析 `stage1`、`bootstrap`、`stage2` 以及隐私相关字段
- 生成当前实验唯一标识和输出目录

### 阶段 1：联邦数据分区准备

在进入联邦轮次之前，先一次性完成客户端分区。

输入：

- 原始训练文本
- 联邦创新算法的分区规则
- `num_clients`
- `validation_ratio`
- `max_samples_per_client`

输出：

- 固定的客户端分区结果
- 每个客户端的训练文本集合
- 可选的客户端验证文本集合
- 客户端元数据映射

内部处理逻辑：

- 完全复用联邦创新算法现有的数据分区规则
- 分区结果在整个实验周期中固定，不在每轮重新切分
- 每个客户端拥有独立私有文本集合
- 如需限制客户端样本量，必须在分区完成后按配置截断

### 阶段 2：联邦轮次初始化

完成分区后，初始化联邦实验状态。

输入：

- 联邦轮次总数
- 客户端分区结果
- 实验配置

输出：

- 联邦轮次调度状态
- 初始 `privacy_ledger.json`
- 实验级统计容器

内部处理逻辑：

- 初始化 round counter
- 初始化实验级隐私记录结构
- 初始化每轮汇总容器
- 准备 per-round 输出目录

### 阶段 3：客户端本地 Stage1

每个联邦 round 中，每个客户端仅运行一次 `stage1`。

输入：

- 当前客户端的私有训练文本
- 当前 round id
- `stage1` 配置
- 当前实验的隐私设置

输出：

- 客户端 `stage1_summary.json`
- 客户端 `surviving_text_it*.json`
- 本轮上传给服务端的 surviving texts

内部处理逻辑：

- 每个客户端只使用自己的私有数据
- `stage1` 算法逻辑保持原样，不引入联邦特化
- 每个客户端本轮只需要把 surviving texts 视作联邦上传对象
- `stage1_summary` 中已有的隐私字段保留原义，不重新定义

### 阶段 4：服务端汇总 surviving texts

服务端在每轮中统一收集所有客户端 surviving texts。

输入：

- 所有客户端本轮 surviving texts

输出：

- 本轮全局 surviving texts 列表
- 本轮 surviving text 数量统计

内部处理逻辑：

- 直接合并所有客户端 surviving texts
- 第一版不做加权、不做筛选、不做聚类
- merged surviving texts 是本轮服务端 `bootstrap` 的唯一输入

### 阶段 5：服务端执行全局 Bootstrap

服务端使用全局 surviving texts 生成 bootstrap 输入。

输入：

- 本轮全局 surviving texts
- `bootstrap` 配置

输出：

- bootstrap 结果
- bootstrap 过程统计

内部处理逻辑：

- 完全复用现有 `PrE-Text` bootstrap 能力
- bootstrap 的输入不再来自单节点全量文本，而是来自联邦汇总 surviving texts
- 本阶段不引入服务端个性化逻辑

### 阶段 6：服务端执行全局 Stage2

服务端在每轮 bootstrap 之后统一执行一次 `stage2`。

输入：

- bootstrap 结果
- `stage2` 配置
- 生成模型配置

输出：

- `server_stage2/llama7b_text_syn.json`
- `server_stage2/stage2_summary.json`

内部处理逻辑：

- 本轮只运行一次全局 `stage2`
- 本轮全局 `stage2` 产物即本轮联邦生成结果
- 该结果用于本轮归档和最终轮结果选取

### 阶段 7：每轮实验产物落盘

每个联邦 round 结束后，立即写出 round artifacts。

输入：

- 客户端 stage1 产物
- 服务端 bootstrap / stage2 产物
- 本轮统计信息

输出：

- `round_xxx/client_xxx/*`
- `round_xxx/server_stage2/*`
- 本轮 round summary

内部处理逻辑：

- 每个客户端目录保留本轮 stage1 summary 和 surviving texts
- 服务端目录保留本轮全局 stage2 产物
- 同时更新实验级 `metrics_summary.json` 和 `privacy_ledger.json`

### 阶段 8：最终语料确定与实验收尾

当联邦轮次全部结束后，只保留最后一轮全局合成语料作为正式实验输出。

输入：

- 所有 round 的服务端 stage2 产物

输出：

- 最终全局合成语料路径
- 最终样本数量统计
- 完整 `metrics_summary.json`
- 完整 `privacy_ledger.json`

内部处理逻辑：

- 不拼接多轮语料
- 不对中间轮次做额外融合
- 最终语料固定取最后一轮的 `llama7b_text_syn.json`
- 该文件应能被后续单机下游评测流程直接读取

## 4. 输入输出定义

### 4.1 实验级输入

实验启动所需输入包括：

- 联邦版 PrE-Text YAML 配置
- 真实私有文本数据集
- 目标数据集名称
- 实验 ID
- 上游生成模型配置
- 隐私预算配置

### 4.2 客户端级输入

每个客户端在每轮 `stage1` 的输入包括：

- 固定客户端私有训练文本
- 客户端验证文本或校验切分
- `stage1` 参数
- 隐私预算字段
- 当前 round id

### 4.3 服务端级输入

每轮服务端的输入包括：

- 所有客户端 surviving texts
- `bootstrap` 参数
- `stage2` 参数
- 生成模型参数

### 4.4 实验级输出

实验完成后必须形成以下核心输出：

- `resolved_config.json`
- `metrics_summary.json`
- `privacy_ledger.json`
- 每轮完整 artifact 目录
- 最终轮全局合成语料文件

### 4.5 最终输出要求

最终交付给后续下游评测的内容必须是：

- 明确可定位的最终语料文件路径
- 可统计的最终样本数量
- 与实验配置一致的隐私记录
- 可追溯到各 round 各 client 的来源信息

## 5. 内部处理逻辑说明

### 5.1 联邦分区逻辑

联邦版 PrE-Text 不自行定义一套新的分区规则，而是直接复用联邦创新算法现有规则。

这样做的目的有两个：

- 保证实验公平性
- 保证联邦创新算法与联邦版 PrE-Text 在客户端数据组织层面对齐

### 5.2 客户端与服务端职责分离

联邦版 PrE-Text 的职责划分必须严格固定：

- 客户端负责 `stage1`
- 服务端负责 `bootstrap -> stage2`

这条边界不能被模糊，否则实验口径会漂移。

### 5.3 上传对象限制

第一版联邦版 PrE-Text 中，客户端每轮上传对象固定为 surviving texts。

这样做的作用：

- 对齐“客户端贡献阶段性结果，服务端做全局生成”的实验机制
- 减少不必要的中间结果传输
- 保持与已确认设计方案一致

### 5.4 隐私口径处理

联邦版 PrE-Text 采用双层隐私记录机制：

- 算法内部隐私口径：继续使用 `PrE-Text` 原生 `stage1` 隐私逻辑
- 联邦实验隐私口径：由编排层汇总成 `privacy_ledger.json`

这样既不破坏算法本体，又能满足联邦实验对齐与核查需求。

### 5.5 最终轮语料口径

联邦版 PrE-Text 正式实验只使用最后一轮全局合成语料。

原因：

- 与联邦创新算法当前“最终轮产物进入下游评测”的机制一致
- 避免多轮合并引入额外实验偏差
- 便于正式实验记录和结果核查

## 6. 开发完成后必须达到的效果

开发完成后，联邦版 PrE-Text 至少要达到以下效果。

### 6.1 实验机制层面

- 能读取联邦版 YAML 配置
- 能按联邦创新算法规则切分多客户端数据
- 能按配置执行多轮联邦 round
- 每轮客户端只运行 `stage1`
- 每轮服务端只运行一次全局 `bootstrap -> stage2`
- 能稳定产出最终全局合成语料

### 6.2 产物层面

- 每个实验都有完整实验根目录
- 每轮都有客户端目录和服务端目录
- 每个客户端有 `stage1_summary.json`
- 每轮服务端有 `llama7b_text_syn.json`
- 有完整 `metrics_summary.json`
- 有完整 `privacy_ledger.json`

### 6.3 可复用层面

- 最终全局合成语料可被现有单机下游评测流程复用
- 联邦版实验口径可与联邦创新算法做公平对照
- 正式实验文档和记录表可据此建立

## 7. 测试与验证方案

### 7.1 配置验证

需要验证：

- 联邦版 YAML 能被正确加载
- `execution.mode = federated_pretext` 生效
- `federation` 字段能够被正确识别
- `stage1/bootstrap/stage2` 参数能保持现有语义

成功标准：

- 配置解析无报错
- 输出 `resolved_config.json`
- 配置字段与输入 YAML 一致

### 7.2 分区验证

需要验证：

- 联邦版 PrE-Text 使用的客户端分区规则与联邦创新算法一致
- 客户端数量、每客户端样本数限制、验证切分比例按配置生效

成功标准：

- 同一数据集、同一分区参数下，联邦版 PrE-Text 与联邦创新算法的客户端数据编排结构一致

### 7.3 流程连通性验证

需要验证一条最小联邦链路：

- 数据分区
- 客户端 stage1
- surviving texts 汇总
- 服务端 bootstrap
- 服务端 stage2
- round artifacts 写出

成功标准：

- tiny 配置可完整跑通
- 不出现 round 中断
- 最终实验根目录生成完整

### 7.4 产物完整性验证

需要验证：

- 每轮都有客户端 stage1 目录
- 每轮都有服务端 stage2 目录
- 每轮有 surviving text 记录
- 实验根目录有 `metrics_summary.json`
- 实验根目录有 `privacy_ledger.json`

成功标准：

- 关键产物文件全部存在
- 文件内容字段齐全
- 产物路径可被正式实验记录表直接引用

### 7.5 结果口径验证

需要验证：

- 最终语料只取最后一轮的全局合成语料
- 最终样本数量与最后一轮 stage2 输出一致
- `metrics_summary.json` 中的最终路径与真实文件一致

成功标准：

- 不使用中间轮语料作为最终实验结果
- 结果口径与联邦创新算法正式实验一致

### 7.6 下游兼容性验证

需要验证：

- 最终轮 `llama7b_text_syn.json` 可直接被现有单机下游评测链路读取

成功标准：

- 不需要对单机下游评测逻辑做结构性改造
- 联邦版 PrE-Text 产物能直接复用
