# 联邦版 PrE-Text 技术开发方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为联邦版 PrE-Text 设计一套可实施的技术方案，明确配置体系、模块边界、代码落点、参数设计、实验矩阵和验证策略，使后续开发能够直接进入实现阶段。

**Architecture:** 以 `PrE-Text/pretext_platform` 为主工程，在不改写 `stage1/bootstrap/stage2` 算法本体的前提下，新增 `federated_pretext` 运行模式、联邦分区复用模块、联邦 runner、artifact 写出和隐私账本汇总模块，并配套联邦实验 YAML 目录。

**Tech Stack:** Python、YAML、JSON、`PrE-Text/pretext_platform` 现有流水线模块、联邦创新算法同口径数据分区规则、现有生成模型与评测链路。

---

## 1. 技术目标

本方案从技术角度回答四类问题：

- 联邦版 PrE-Text 的代码应当如何组织
- 实验配置应当如何设计
- 参数和超参数如何暴露到 YAML
- 如何验证实现结果与设计方案一致

本方案的核心要求是：

- 单节点版 PrE-Text 保持原状
- 联邦版 PrE-Text 在 `PrE-Text/pretext_platform` 中独立落地
- 联邦版与联邦创新算法在实验编排层保持对齐
- 最终所有关键切换都通过 YAML 完成

## 2. 推荐代码落点

### 2.1 新增模块

建议新增以下模块。

#### `PrE-Text/pretext_platform/core/federated_runner.py`

职责：

- 联邦版 PrE-Text 总调度入口
- 解析实验配置后的联邦运行逻辑
- 控制 round loop
- 调度客户端 stage1 与服务端 bootstrap/stage2
- 汇总 round 结果
- 产出实验级 summary

推荐包含的能力：

- 联邦实验初始化
- round 调度
- per-client 执行封装
- 服务端执行封装
- 最终语料确定

#### `PrE-Text/pretext_platform/core/federated_partition.py`

职责：

- 复用联邦创新算法的数据分区规则
- 将原始数据整理为联邦版 PrE-Text 所需的客户端输入结构

推荐包含的能力：

- 数据集加载后分区
- 训练/验证切分
- `max_samples_per_client` 处理
- 客户端样本映射输出

#### `PrE-Text/pretext_platform/core/federated_artifacts.py`

职责：

- 统一处理实验根目录与 round 目录写出
- 统一写出 `metrics_summary.json`
- 统一写出 per-round client/server artifacts

推荐包含的能力：

- 实验目录初始化
- round 目录命名
- 客户端目录写出
- 服务端目录写出
- 最终 summary 汇总

#### `PrE-Text/pretext_platform/core/federated_privacy.py`

职责：

- 从每个客户端 `stage1_summary.json` 中抽取隐私信息
- 汇总到联邦实验级 `privacy_ledger.json`

推荐包含的能力：

- 每轮隐私记录组装
- 全实验隐私汇总
- 最终 `privacy_summary` 聚合

### 2.2 建议修改的现有模块

#### `PrE-Text/pretext_platform/core/pipeline.py`

修改目标：

- 支持通过 `execution.mode` 分发运行模式

建议语义：

- `single_node` 继续走现有单节点流程
- `federated_pretext` 转发到联邦 runner

#### `PrE-Text/pretext_platform/core/config.py`

修改目标：

- 配置解析层新增 `execution` 与 `federation` 字段

建议语义：

- 支持联邦模式配置读取
- 为联邦实验提供统一访问接口

#### `PrE-Text/pretext_platform/scripts/run_pipeline.py` 或现有入口脚本

修改目标：

- 允许直接加载联邦版 YAML 并走统一入口

另外可增设：

- `PrE-Text/pretext_platform/scripts/run_federated.py`

作用：

- 便于本地单独调试联邦版 PrE-Text

## 3. 配置体系设计

### 3.1 顶层配置结构

联邦版 PrE-Text 配置建议增加以下顶层区块：

```yaml
experiment_id: fpt_jobs_eps129
output_root: outputs/pretext_platform

execution:
  mode: federated_pretext

dataset:
  name: jobs
  format: raw_text
  train_path: ...

federation:
  rounds: 3
  num_clients: 8
  partition_strategy: preserve_buckets
  validation_ratio: 0.25
  max_samples_per_client: 16

stage1:
  ...

bootstrap:
  ...

stage2:
  ...

privacy:
  ...

evaluation:
  ...
```

### 3.2 `execution` 区块

推荐字段：

- `mode`

合法值：

- `single_node`
- `federated_pretext`

用途：

- 控制单节点与联邦版执行入口

### 3.3 `federation` 区块

推荐字段：

- `rounds`
- `num_clients`
- `partition_strategy`
- `validation_ratio`
- `max_samples_per_client`

字段说明：

- `rounds`
  - 外层联邦轮次数
- `num_clients`
  - 客户端总数
- `partition_strategy`
  - 必须与联邦创新算法使用同一语义
- `validation_ratio`
  - 每个客户端本地验证切分比例
- `max_samples_per_client`
  - 每个客户端使用的最大私有样本数

### 3.4 `stage1/bootstrap/stage2` 区块

联邦版不重新定义它们的内部参数，只改变调用层级。

技术要求：

- `stage1` 参数直接用于客户端本地执行
- `bootstrap` 参数直接用于服务端全局 bootstrap
- `stage2` 参数直接用于服务端全局 stage2

### 3.5 `privacy` 区块

技术要求：

- 保持与现有 PrE-Text 单节点语义一致
- 不新造一套联邦隐私数学
- 联邦编排层只负责提取并记录

推荐记录字段：

- `enabled`
- `epsilon`
- `delta`
- 其他当前 `stage1` 已使用字段

### 3.6 `evaluation` 区块

联邦版生成阶段本身不做联邦评测，但建议保留评测区块，原因是：

- 后续单机下游评测仍需读取同一配置或派生配置
- 正式实验记录时需要明确最终评测口径

建议继续统一为：

- `gpt2`

说明：

- 当前正式实验口径继续使用 `gpt2`
- `distilgpt2` 仅是本地模型目录名，不作为正式实验模型口径

## 4. 实验配置目录设计

### 4.1 目录位置

建议新建：

- `PrE-Text/configs/experiments/federated/`

作用：

- 专门放联邦版 PrE-Text YAML
- 避免与单节点配置混用

### 4.2 命名规则

统一前缀：

- `fpt_` = federated pretext

推荐基础正式实验命名：

- `fpt_jobs_eps129.yaml`
- `fpt_jobs_eps05.yaml`
- `fpt_jobs_eps758.yaml`
- `fpt_jobs_no_privacy.yaml`
- `fpt_congressional_eps129.yaml`
- `fpt_forums_eps129.yaml`
- `fpt_microblog_eps129.yaml`

推荐验证配置命名：

- `fpt_jobs_tiny.yaml`
- `fpt_jobs_validate.yaml`

### 4.3 正式实验矩阵建议

联邦版 PrE-Text 正式实验建议分三组。

#### 组 1：核心数据集主表

- `jobs`
- `congressional`
- `forums`
- `microblog`

统一控制：

- 相同默认隐私预算
- 相同生成模型
- 相同联邦轮次
- 相同最终导出样本数

#### 组 2：隐私预算表

以 `jobs` 为主：

- `eps0.5`
- `eps1.29`
- `eps7.58`
- `no_privacy`

用途：

- 与联邦创新算法做公平隐私对照

#### 组 3：验证与冒烟配置

- tiny 配置
- validate 配置

用途：

- 开发时快速验证联邦链路和产物完整性

## 5. 超参数设计建议

### 5.1 联邦层超参数

联邦层需要通过 YAML 暴露的参数包括：

- `federation.rounds`
- `federation.num_clients`
- `federation.validation_ratio`
- `federation.max_samples_per_client`
- `federation.partition_strategy`

这些参数决定联邦实验机制本身，必须全部可配置。

### 5.2 Stage1 相关参数

保留当前 PrE-Text 的原生参数暴露方式。

重点要求：

- 不要把客户端 stage1 参数写死在 runner 中
- 必须能通过配置文件切换隐私预算、阈值、迭代次数等参数

### 5.3 Bootstrap 相关参数

Bootstrap 相关参数也必须继续 YAML 驱动。

重点要求：

- 服务端 bootstrap 的输入规模不能写死
- 全局 surviving texts 的使用方式要可从现有 bootstrap 参数体系衔接

### 5.4 Stage2 相关参数

建议重点暴露以下参数：

- 生成模型名称
- 生成样本数量
- 每轮 stage2 的生成控制参数

技术目标：

- 联邦版正式实验能直接通过 YAML 调节最终合成样本数
- 与联邦创新算法在“最终导出样本数”维度保持可公平对照

## 6. 实验输出设计

### 6.1 输出根目录

建议沿用：

- `PrE-Text/outputs/pretext_platform/<experiment_id>/`

原因：

- 不需要引入第二套输出系统
- 只通过实验 ID 和内部结构区分联邦版与单节点版

### 6.2 Round 目录结构

建议固定为：

```text
<experiment_id>/
  resolved_config.json
  metrics_summary.json
  privacy_ledger.json
  round_000/
    client_000/
      stage1_summary.json
      surviving_text_it0.json
    client_001/
      stage1_summary.json
      surviving_text_it0.json
    server_stage2/
      llama7b_text_syn.json
      stage2_summary.json
  round_001/
    ...
```

### 6.3 `metrics_summary.json`

建议字段：

- `experiment_id`
- `experiment_dir`
- `status`
- `round_count`
- `completed_rounds`
- `final_synthetic_corpus_path`
- `final_synthetic_sample_count`
- `round_summaries`
- `privacy_summary`

### 6.4 `privacy_ledger.json`

建议字段：

- `schema_version`
- `experiment_id`
- `rounds`
- `round_records`
- `final_privacy_summary`

每轮建议记录：

- `round_id`
- `participating_clients`
- `client_stage1_stats`
- `merged_surviving_count`
- `server_stage2_sample_count`

## 7. 测试方案设计

### 7.1 单元级验证

建议覆盖：

- 联邦配置解析
- 联邦分区结果结构
- round artifact 路径构造
- privacy ledger 汇总结构

目标：

- 保证联邦新模块的基础行为稳定

### 7.2 集成级验证

建议至少有一条 tiny 联邦配置，用于跑通完整闭环：

- 数据加载
- 联邦分区
- 客户端 stage1
- 服务端 bootstrap
- 服务端 stage2
- 最终 summary 写出

目标：

- 确认联邦 runner 真正可执行

### 7.3 对齐性验证

建议验证：

- 联邦版 PrE-Text 的分区规则与联邦创新算法一致
- 联邦版最终只使用最后一轮语料
- 联邦版最终语料可进入现有单机评测链路

目标：

- 保证实验公平性和结果可比性

### 7.4 正式实验前验证

在大规模正式实验前，必须先通过：

- tiny 冒烟
- validate 配置
- 产物完整性检查
- 一组标准数据集的联邦试跑

## 8. 开发实施顺序建议

### 8.1 第一阶段：配置与入口

- 在配置层加入 `execution` 和 `federation`
- 打通 `pipeline` 到联邦 runner 的分发
- 准备 `fpt_jobs_tiny.yaml`

### 8.2 第二阶段：联邦闭环

- 复用分区规则
- 打通客户端 stage1
- 打通服务端 bootstrap -> stage2
- 写出最小 round artifacts

### 8.3 第三阶段：产物与隐私账本

- 完成 `metrics_summary.json`
- 完成 `privacy_ledger.json`
- 完成最终轮语料确定

### 8.4 第四阶段：正式实验资产

- 新建 federated 配置矩阵
- 输出正式实验设计文档
- 输出实验记录表

## 9. 开发完成后的技术验收标准

### 9.1 功能验收

- 联邦配置能跑通
- 多客户端 stage1 能执行
- 服务端 bootstrap/stage2 能执行
- 最终轮语料能生成

### 9.2 结构验收

- 新模块职责清晰
- 单节点路径未被破坏
- 联邦版输出结构稳定

### 9.3 公平性验收

- 分区规则与联邦创新算法一致
- 正式实验关键口径一致
- 下游评测语料来源一致

### 9.4 可扩展性验收

- 后续能继续扩展正式实验配置
- 后续能加入 resume 或失败恢复，而不需要推翻现有结构
