## 一、完整版第三版算法设计（理论目标）

### 1.1 算法核心思想

第三版创新算法 **FedText-Proto** 是基于**原型锚点的个性化联邦提示词优化框架**，旨在解决 Non-IID 数据分布场景下的文本合成数据优化问题。核心创新是引入**原型向量 (Prototype)** 作为客户端与服务端之间的分布坐标，实现精准的个性化路由。

### 1.2 完整算法四阶段流程

#### 第一阶段：客户端多维度辅助信息提取与传输

**目标**: 从单一文本反馈升级为包含"指令、坐标、权重"的三维结构化反馈

**步骤 1.1: 效用驱动的坏样本诊断**
- 客户端 k 收到服务端用 P_t 生成的合成样本 x_syn
- 利用本地私有验证集，通过 DataInf（基于梯度的影响函数）评估 x_syn 对本地模型损失的恶化程度
- 将恶化程度映射归一化为效用奖励分数 R_k ∈ [0, 1]
- R_k 越大，代表该合成样本"毒性"越强

**步骤 1.2: 语义原型的锚定提取**
- 针对毒性最高的 x_bad，召回对应的本地真实高质量样本 x_real
- 通过轻量级冻结的特征提取器（如 BERT/MiniLM 的 Embedding 层），计算真实样本的均值特征向量
- 输出局部语义原型向量 Z_k = mean(Embed(x_real))
- 代表该客户端独特的数据分布流形

**步骤 1.3: 文本化梯度生成**
- 本地小模型（如 Qwen-1.5B）对比 (x_bad, x_real)
- 生成自然语言修改意见 g_text^k

**步骤 1.4: 三元组打包上传**
- 客户端打包上传三元组 Γ_k = {g_text^k, Z_k, R_k}

#### 第二阶段：服务端基于原型的概率对齐与加权聚类

**目标**: 在高维空间中，利用"分布坐标"而不是"字面意思"进行精准聚类

**步骤 2.1: 隐空间原型聚类**
- 服务端收到所有 Γ_k 后，先看原型 Z_k
- 在多维隐空间中，对所有原型向量 {Z_1, Z_2, ..., Z_N} 应用 GMM 或 DBSCAN
- 将 N 个客户端严格划分为 M 个非重叠的语义簇 (Clusters)
- 簇 C_1 聚集所有心脏病分布，簇 C_2 聚集所有骨科分布

**步骤 2.2: 效用加权的注意力分配**
- 在同一簇 C_m 内部，不同客户端受害程度不同
- 服务端利用效用分数 R_k 对同簇内的文本梯度进行加权
- α_k = exp(R_k) / Σ exp(R_i)
- 确保痛点最深的客户端在后续冲突消解中拥有最大"话语权"

#### 第三阶段：SVD 冲突解耦与 KKT 缓解投射

**目标**: 在同一簇内，通过严格的数学空间投射，剥离有效建议，拦截相互打架的"恶性冲突"

**步骤 3.1: 正交解耦提取**
- 将簇内的文本梯度转化为文本 Embedding 向量
- 应用 SVD 奇异值分解
- 第一奇异向量（主成分方向）代表该簇所有人的共识性修改意见
- 剩余正交方向代表局部的个性化意见

**步骤 3.2: 有害冲突拦截 (KKT 条件)**
- 检查文本向量之间的余弦相似度
- 若向量 v_a 与 v_b 的点积小于 0（夹角 > 90°），触发恶性冲突
- 例如"加长"与"缩短"方向的冲突
- 利用 KKT 条件进行梯度手术
- 将弱势方的冲突分量向强势方的法平面进行正交投影
- 强行剔除负向抵消的部分
- 输出绝对安全的"无冲突核心指令集"

#### 第四阶段：异构双提示词架构重构与下发

**目标**: 拒绝"一刀切"，实现"求同存异"的定制化合成数据生成

**步骤 4.1: 全局共享提示词生成**
- 服务端 LLM 将所有 M 个簇的无冲突主成分翻译为全局基座提示词 P_global^{t+1}
- 例如："所有输出必须采用客观、严谨的临床医学术语，禁止使用口语化表达"

**步骤 4.2: 本地定制提示词生成**
- 针对每个特定簇 m，服务端 LLM 将该簇独有且通过了 KKT 检测的正交个性化意见
- 翻译成该簇专属的定制提示词 P_local^{t+1, m}
- 例如心血管簇："必须详细包含心电图（ECG）读数，特别是 ST 段抬高等核心生理生化指标"

**步骤 4.3: 定向路由下发**
- 在生成下一轮数据时，针对簇 C_m 的客户端
- 服务端采用组合 Prompt = [P_global^{t+1} ⊕ P_local^{t+1, C_m}] 进行生成
- 按比例混合：α 份个性化数据 + (1-α) 份全局数据
- 完美契合各客户端的 Non-IID 需求

### 1.3 完整算法数学表达

**客户端上传**:
```
Γ_k = {g_text^k, Z_k, R_k}

其中:
- g_text^k: 自然语言修改建议 (文本梯度)
- Z_k = (1/|D_k|) Σ Embed(x_real): 原型向量
- R_k: 效用分数，基于 DataInf 梯度影响计算
```

**原型聚类**:
```
C_m = DBSCAN({Z_k | k = 1...N}, eps, min_samples)
```

**注意力加权**:
```
α_k = exp(R_k) / Σ_{j ∈ C_m} exp(R_j)
```

**SVD 主轴提取**:
```
[U, S, V^T] = SVD(X)
P_consensus = V[0]  # 第一主成分 = 共识方向
P_personal = V[1:]  # 残差 = 个性化方向
```

**KKT 冲突投影**:
```
若 cos(v_a, v_b) < 0 且 weight(v_a) < weight(v_b):
    v_a_proj = v_a - (v_a · v_b_normalized) * v_b_normalized
```

**双层 Prompt 生成**:
```
P_global^{t+1} = LLM_summarize({P_consensus_m | m = 1...M})
P_local^{t+1, m} = LLM_summarize({P_personal_m | m = 1...M})
```

**个性化数据路由**:
```
D_client_k = α * D_generated(P_local^{t+1, C_k}) + (1-α) * D_generated(P_global^{t+1})
```

## 三、逐模块对比：完整版 vs 当前实现

### 3.1 第一阶段对比表

| 子模块 | 完整版设计 | 当前实现 | 差距 |
|--------|-----------|----------|------|
| DataInf 坏样本诊断 | 基于 LoRA 微调的梯度/HVP 计算，输出 R_k 效用分数 | 基于 Roberta 特征的相似度计算，近似影响分数 | **重大差距**：无真实梯度计算，无 R_k 分数 |
| 原型向量提取 Z_k | 用冻结特征提取器提取真实样本均值 | 用 MiniLM 提取 retrieval 结果均值 | **部分差距**：特征提取器不同，权重定义不同 |
| 文本梯度生成 g_text | 本地小模型对比 (x_bad, x_real) | 本地 LLM 对比 (PairedSample) | **已完成** |
| 三元组上传 Γ_k | {g_text, Z_k, R_k} 完整上传 | {g_text, Z_k, weight}，weight ≠ R_k | **部分差距**：weight 定义不同 |
| 隐私重化 | NER + 正则脱敏 + compression | 基础数字/实体替换 + 脱敏 | **部分完成** |

```python
# 每轮应执行：
gradients_clipped = [clip(g, C) for g in client_gradients]
noisy_gradients = [g + GaussianNoise(σ, δ, ε) for g in gradients_clipped]
```

**当前实现**:
```python
# 只有记账：
privacy_spent = sample_count * sample_cost + critique_count * critique_cost
# 无 clip，无 noise injection
```

**影响**: 无法真实评估隐私保护效果

#### 差距 2: R_k 效用分数未正确计算

**完整设计**: R_k = DataInf 梯度影响分数（归一化到 [0,1]）

**当前实现**:
```python
avg_bad_score = sum(float(sample.score) for sample in selected_bad) / len(selected_bad)
# weight = avg_bad_score, 而非真正的 R_k
```

**影响**: 客户端重要性权重不正确，聚合时注意力分配不准确

#### 差距 3: KKT 投影解耦未实现

**完整设计**:
```python
# 弱势方投影到强势方法平面
v弱势_proj = v弱势 - (v弱势 · v强势_normalized) * v强势_normalized
```

**当前实现**:
```python
# 仅筛除弱势方
if cos < 0 and weight_weak < weight_strong:
    dominated = True  # 直接丢弃
```

**影响**: 无法实现真正的"冲突消解"，可能丢失有效信息

### 4.2 P1 级差距（影响算法精度）

#### 差距 4: DataInf 不是论文级实现

**问题**: datainf_real 使用 Roberta 特征空间做相似度计算，而非真实 LoRA 微调的梯度/HVP 计算

**影响**: 坏样本识别精度可能不如真实 DataInf

#### 差距 5: 效用加权注意力未实现

**完整设计**:
```python
α_k = exp(R_k) / Σ_{j ∈ C_m} exp(R_j)
```

**当前实现**: 未实现，所有客户端等权重

#### 差距 6: 混合比例固定，非动态调整

**完整设计**: α 应基于实验或动态计算

**当前实现**: 固定 `personalized_mix_ratio = 0.7`

#### 差距 7: 双层 Prompt 组合方式简单

**完整设计**: P_combined = [P_global ⊕ P_cluster] 结构化组合

**当前实现**: `render_cluster_prompt()` 简单拼接

### 4.3 P2 级差距（影响实验完整性）

#### 差距 8: 实验配置矩阵不完整

**缺失配置**:
- `jobs_real_gradmm_v3.yaml`
- `jobs_real_ira_v3.yaml`
- `jobs_real_datainf_v3_eps758.yaml`

- `code_real_*`

#### 差距 9: Code 数据域缺失

**缺失**: `pretext_code` 数据集

#### 差距 10: small-eval 未接通

**缺失**: `c4_checkpoint.pth`

#### 差距 11: 正式实验结果未沉淀

**问题**: 仓库内无 `jobs_real_datainf_v3` 结果目录

### 4.4 P3 级差距（工程优化项）

## 六、关键差异总结

### 6.1 算法核心差异

| 方面 | 完整版设计 | 当前实现 | 差距级别 |
|------|-----------|----------|----------|

| DP 机制 | 真实 clip + noise | 仅记账 | P0 |
| 混合比例 | 动态/最优搜索 | 固定 0.7 | P2 |
